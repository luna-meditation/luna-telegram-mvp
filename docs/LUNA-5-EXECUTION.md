# Luna 5.0 — реализация, проверка и безопасный релиз

Все шесть частей ТЗ и дополнение прочитаны 20 октября 2026 года.
Базовая production-версия: `949d7d2857c65724f2e90d2046a38cb83c3a8c27`.
Ветка: `feature/luna5-personal-intelligence`. Работа ведётся в отдельном
локальном worktree; чужие изменения и удаления в прежнем checkout не тронуты.

## Ограничения релиза

- Одна итоговая frontend-публикация Netlify, обычная стоимость 15 кредитов.
- Ноль staging-публикаций, Agent Runner, AI Gateway и новых сервисов.
- Новые платные AI/STT-тесты не запускались. Старый QA-бюджет Luna 4.0 закрыт.
- Модель `gpt-5-mini`, лимит $100, действующие квоты, цены, Beta и права сохранены.
- Нет реальных тестовых покупок, сброса балансов или production QA-записей.
- Качество живого диалога и финальный вид на физическом iPhone проверяет владелец.
  Локальные тесты не объявляются доказательством субъективного AI-качества.

## Причины и реализованные изменения

| Область | Причина / решение | Граница доказательства |
| --- | --- | --- |
| Личный контекст | Общая ограниченная проекция существующих подтверждённых записей и канонического self-профиля; обратная связь привязана к точному natal/Tarot ID | Unit/integration fixtures; нет второго хранилища памяти |
| Короткие ответы | В conversation_state хранится актуальный вопрос, тема, до трёх вариантов и время; ответы «Да», «Опрос», «первый» связаны с этим вопросом, а не с устаревшим intent | Сохранение JSON в native PostgreSQL; не является разрешением на покупку или сохранение факта |
| Смена темы | Явный новый запрос прерывает прежний вопрос; возврат восстанавливает его; устаревшие/невалидные состояния отбрасываются | RU/EN тесты контекстных переходов |
| Новый вход | Убрано автоматическое открытие последнего localStorage thread; история доступна через явное продолжение | Перезагрузка документа и переключение вкладок проверены отдельно |
| Приветствие | Детерминированная дневная проекция по IANA timezone, local date, owner, версии источников/расчёта и языку; скрытие на сегодня и opt-out | Ноль provider-вызовов; солнечная рефлексия не выдаётся за транзитный прогноз |
| Согласия | Передача новых расчётных символических данных в AI требует отдельного добровольного symbolicAiContext; прежнее согласие не расширено автоматически | По умолчанию выключено; сырые дата/время/место не входят в эту проекцию |
| My Cosmos | Шесть компактных глав, живые подтверждённые записи, источники и отдельная интерактивная небесная композиция; старые анкетные входы убраны из обычного пути | Декоративное созвездие явно не является натальной картой |
| Знакомство | Кнопка открывает существующее контекстное обсуждение портрета и обычный chat/voice, без прежних семи шагов | Данные старого знакомства не удаляются; ручные коррекции остаются в приватности |
| Tarot | Раньше финальный reveal ждал AI. Теперь reveal сохраняется отдельно, UI открывает карту сразу, интерпретация запускается отдельно | Тот же draw/history/order/accounting; атомарная отметка попытки и чтение статуса вместо повторного POST |
| Numerology | Пять расчётных чисел раскрывают метод, традиционный смысл и ограничения прямо в контексте | Существующий детерминированный движок не заменён |
| Astrology / pair | Сохранены Astronomy Engine, Temporal, версии и cache ключи, self/pair authorization и существующие saved reports | Повторно используются небольшие NASA/JPL/DST/unknown-time/synastry fixtures; нового внешнего бенчмарка нет |
| Voice / practices | Работающие запись, редактируемая транскрипция, реальные playable cards и breathing engine не переписаны | Автотесты сохранены; новая запись на физическом iPhone требует проверки владельца |

Существующие paid-product hashes и финансовые модули защищены release gate от
изменения. Исторические AI-отчёты не перегенерируются ради нового вида интерфейса.

## Измерение Tarot

Сервер пишет только агрегированные длительности authorization, persistence,
reading, progress, render, interpretation и total, без вопроса, birth details и
идентификаторов пользователя. Frontend измеряет reveal request, optimistic
render и отдельный interpretation request. Название, положение и позиция карты
не зависят от готовности AI.

После последней карты: «Луна соединяет значения карт…» / «Luna is bringing your
cards together…». Повторное открытие готового/ошибочного результата не запускает
генерацию. При потере ответа выполняется ограниченное GET-наблюдение; reconnect
не повторяет платный POST. Новый lifecycle хранится рядом с metadata.tarot, а не
внутри прежнего strict-объекта: старый backend сможет прочитать сохранённые карты.

Локальная браузерная фикстура использует задержку сохранения 300 ms и тестовую
интерпретацию 2200 ms. Это проверка независимости критического пути, не замер
production/OpenAI latency. Одинаково мгновенную генерацию приложение не обещает.

## Порядок выпуска и откат

1. Фиксированные исходники → TypeScript/lint/build/unit/native role+rollback/mobile.
2. Проверка свежести/целостности независимой копии и финансовых контрольных хэшей.
3. Development commit и PR, merge с [skip netlify]; одна Railway backend-сборка.
4. Backend health: точный merge SHA, верный Supabase, модель, права и настройки.
5. Локальный production build: реальный Telegram SDK, правильные API/bot/SHA,
   отсутствие preview bridge, secret и QA functions; одна Netlify --prod публикация.
6. Read-only smoke публичных страниц/assets/API и контроль финансовых хэшей.

Предыдущий Netlify deploy: `6ad62cdf1cfb896e28f8aab0`.
Предыдущий Railway deploy: `ab58fb5b-3e1e-4aa2-bdc5-bad86af18ac6`.
При необходимости вернуть эти artifacts; не восстанавливать целиком старую базу
поверх новых пользовательских записей. Narrow REVOKE не требует обратного GRANT
для отката приложения: оба backend используют тот же service_role. Копия БД —
для изолированного восстановления/выборочного recovery после отдельной проверки.
Не запускать автоматический второй Netlify deploy, если критический smoke не прошёл.

## Оставшиеся ограничения / iPhone acceptance

- Свежий provider benchmark и живой субъективный диалог не выполнялись по политике
  расходов владельца. Модель и маршрутизация не заменены; обещаний нового качества нет.
- Дневной вход использует явно обозначенную солнечную символическую рефлексию,
  даже при наличии natal chart; это не персональные текущие транзиты.
- Если процесс погиб после атомарной отметки interpretationAttempted, история
  безопасно читается, но автоматического повторного платного запроса нет.
- Детерминированные numbers используют документированные UTC calendar periods;
  дневное приветствие отдельно использует IANA timezone пользователя.
- Приложение сохраняет действующую dark-only политику; OS Light не включает
  неподдерживаемый новый Light UI.
- Основной Vite chunk остаётся больше рекомендованных 500 kB; сборка не падает.
