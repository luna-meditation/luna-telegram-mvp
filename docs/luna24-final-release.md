# Luna 2.4: проверенный план выпуска

## Область релиза

- Интерактивные расклады 1/3/5 карт внутри существующего Luna AI: серверный выбор карт, последовательное открытие, сохранение и повторное открытие без генерации.
- Полноширинный блок, карусель с видимой следующей картой, счётчиком и доступными кнопками; позиция сохраняется локально по уникальному ID расклада.
- Компактная шапка чата. Обсуждение использует стабильный request ID и загружает сохранённый разговор целиком, включая первый ответ.
- Новый структурированный AI-ответ версии 2; старые сохранённые ответы не переписываются. Ошибки/неполные ответы переходят к локальным значениям без платного retry.
- Память Luna 2.3, платежи, цены, подписки и Moon Seeds сохраняются.

Единственная новая миграция: `20261015115049_luna24_release_qa_ai_budget.sql`. Добавляет только два Luna QA budget объекта и два RPC SECURITY INVOKER. ## QA AI и расходы

В production AI 3/5 включается только для Telegram QA ID 158467796 через отдельный серверный флаг `FEATURE_TAROT_RELEASE_AI_QA` и отдельный grant до $0.02. Staging grant не переносится и не сбрасывается. Все остальные пользователи получают интерактивные карты и локальные значения. Новые механики монетизации остаются выключенными.

До каждого provider call резервируется консервативная сумма $0.012, после ответа фиксируется фактический расход по токенам. Неопределённый результат удерживает резерв; повторный запрос того же чтения запрещён. Ключ OpenAI остаётся на Railway. Модель gpt-5-mini, стандартный tier, store=false, без tools.

Один production Netlify publish, без новых staging/PR Preview. Автоматические PR Preview отключены отдельно от production main. Перед релизом остаток Netlify: 81.4 кредита; ожидаемый расход публикации 15 кредитов плюс трафик.

## Порядок применения и отката

1. Сравнить точные production fingerprints схемы, функций, RLS и защищённых данных с preflight. При расхождении остановиться.
2. Применить только согласованную QA budget миграцию. Проверить неизменность всех прежних объектов и запреты anon/authenticated.
3. Создать отдельный owner-only grant, подготовить серверные флаги без автоматического deploy. Merge через PR в main с `[skip netlify]`.
4. Дождаться backend SUCCESS. Выполнить один startup-only QA расклад на три карты с ограниченным grant, проверить ready, usage, сохранение/повторное открытие и неизменность профиля/сада/баланса.
5. Только после успешной проверки backend опубликовать один локально проверенный frontend artifact с точным main SHA. Проверить Netlify Ready, health, статические assets и публичный интерфейс.
6. При проблемах до публикации frontend оставить прежний frontend live. Немедленный безопасный kill switch: отключить QA grant и `FEATURE_AI_CENTRAL_EXPERIENCE`/`FEATURE_TAROT_RELEASE_AI_QA`. При необходимости вернуть прежний проверенный backend artifact a8a0ea7e-4bf1-4b7e-905f-d34c251b8352 и frontend 6ad07fe6e08ce1317f93556b. Сохранённую историю не удалять. Новые пустые объекты можно удалить только после архивации audit; предпочтителен недеструктивный откат отключением флага/grant.

## Проверка владельцем на iPhone

Полностью закрыть старое окно Luna, открыть основной бот → Luna AI → Таро → 1/3/5 карт. Открыть карты по порядку, пролистать, увеличить и закрыть системной кнопкой Back. Перейти в другой tab, вернуться и перезапустить приложение: карты и позиция должны сохраниться. Нажать «Обсудить с Luna», затем повторить: второй ответ не создаётся. Проверить RU/EN, Light/Dark, настоящую клавиатуру и safe areas. Платежи во время QA не совершать.
